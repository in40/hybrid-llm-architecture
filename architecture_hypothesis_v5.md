# 📘 Архитектурная гипотеза и экспериментальный протокол: гибридный MoE-декодер с доменной адаптацией для русского/специализированного домена

**Версия:** 5.0
**Статус:** рабочая гипотеза и экспериментальный протокол. Не финальный дизайн.
**Предыдущая:** v4.0 (заморожена). Изменения — только через новую версию с документированием причины.
**Что определяет финальную архитектуру:** результаты абляций на прокси-модели ~150M–1B.
**Что считается успехом:** конфигурация, оптимизированная под наши критерии (домен, бюджет инференса, требования к контексту), а не под лидерборд и не под совпадение с существующей моделью.
**Стратегия:** два параллельных трека — низкорисковый инженерный (Трек A) и высокорисковый лингвистический (Трек B). ОпциональныйTracks C (diffusion) — гейтирован. Отрицательный результат валиден.

## 🆕 Что нового в v5.0 (чейнджлог v4.0 → v5.0)

**Методологические fuse'ы (новые, обязательные):**
- **Regularization-alignment fuse** — сравнение архитектур некорректно без выравнивания стека стохастической регуляризации (token-dropout, MLP-dropout, weight-decay, label-smoothing). Источник: super-data-learner эффект dLLM = token dropout, а не двунаправленность.
- **Cross-paradigm BPB fuse** — AR NLL и dLLM NELBO несопоставимы «в лоб»; нужен единый BPB-эквивалент (variance-reduced ELBO + та же NFC-байтовая нормализация) до любого кросс-парадигмного сравнения.
- **Metadata guards (A–D)** — prepended-метаданные вне 13-gram/MinHash/SHA дедупликации; вне BPB-знаменателя (masked loss); cooldown 10–20% шагов обязателен; metadata = часть regularization-alignment fuse.
- **Proxy-transfer fuse** — ранжирование датасетов/гиперпараметров на прокси переворачивается при смене LR (ICLR2026); для сравнения рецептов — tiny-LR (1e-5–1e-6); абсолютные значения перепроверять на целевом масштабе.

**Новые компоненты пространства поиска:**
- **§2.9 Стохастическая регуляризация** (token-dropout / EntroDrop / curriculum / MLP-dropout / weight-decay).
- **§2.10 Metadata conditioning** (URL/домен prepending + MeCo cooldown; форматные теги для steering; DCLM quality-score как fine-grained сигнал).
- **§2.11 Diffusion / block-diffusion** (кандидат Track C, гейтирован crossover-экспериментом H1).

**C0-специфика (из ТЗ и ревью A1–C6, T_cutoff):**
- 2.5B токенов, `max_steps 9500`, `warmup 500`; словарь **50K** единый; **MHA**; **🆕 C0-прокси ≈152M (tied)** — см. «Примечание о размере прокси»; FLOP-matched референс **≈2.28e18** (`6·152M·2.5B`); 3 сида (2 запрещены); BPB primary + двойной val-лог; V-B 8 ячеек ≤2048; IAA κ≥0.6; T_cutoff **2024-01-01**; T без PII; write-once снимки; pre-registered порог сигнала CI-lower ≥1% rel.

**🆕 Примечание о размере прокси (решение v5.0):** «125M» — **метка класса, а не цель**. Решение B2 (словарь 50K для русского) раздувает эмбеддинги: 12L/768/3072 + 50K vocab = **~152M при tied** (embed=lm_head) / ~190M untied. Принято: **tied, ~152M**, и FLOP-референс **перевыведен** под фактический N: `6·152M·2.5B ≈ 2.28e18` (исходно было 1.875e18 при наивных 125M). Все гейты (сигнал ≥1% rel BPB, FLOP-matching гибрида/MoE) привязаны к фактическому N — использовать 2.28e18. 125M не самоцель; честный размер важнее круглой цифры.

**Инструменты (задел на домен):** PII-редакция (regex+parallel+Natasha PER+stoplist), Yargy (договор поставки), конвертер JSONL→CoNLL-U для Slovnet fine-tune.

# Часть I. Гипотеза

## 1. Критерии успеха и методологические fuse'ы

### 1.1. Критерии (фиксируются до абляций)

| Критерий | Цель | Как измеряем |
| :--- | :--- | :--- |
| Качество (нормализованное) | BPB ≤ X на held-out | bits-per-byte (primary), BPC secondary — не токенный PPL |
| Качество (доменное) | Downstream ≥ Y | Задачи, независимые от токенизации: извлечение, QA, классификация, ranking |
| Скорость генерации | ≥ Z символов/с **и** байтов/с (раздельно) | Не токены/с |
| Стоимость (FLOPs-bound) | Throughput при фикс. бюджете | Декодирование |
| Стоимость (memory-bound) | HBM BW ≤ B ГБ/с на токен | Expert fetch, sharding, prefetch |
| Память на запрос | ≤ M байт @32K | KV + recurrent (GDN) + MTP + lookup + MoE буферы |
| Prefill latency | ≤ P мс @32K | Профилирование |
| Batched throughput | ≥ Q ток/с @batch 8/32 | mixed/same-domain |
| Хвостовые задержки | p95/p99 ≤ R мс | Профилирование |
| Эффективность по данным | BPB ≤ X за ≤ T байт | Кривая BPB vs байты |
| Стабильность обучения | Нет неустранимых спайков | Grad norm, активации, FP8 |
| Expert Health | Collapse ≤ C% | Энтропия маршрутизации, grad norm по экспертам |
| Macro-router | Entropy ≥ E, Prefetch hit ≥ H | Иерархический MoE |
| Contamination audit | 0 точных попаданий | Lookup-таблица без оценочных фрагментов |

### 1.2. Методологические fuse'ы (защита от самообмана)

1. **Tokenizer-normalization fuse.** Токенизаторы сравниваются только по BPB/BPC и downstream, не зависящим от токенизации. BPB = `CE_nats_per_token / (ln2 × bytes_per_token)`, `bytes_per_token = total_UTF8_bytes / total_tokens`, **NFC-нормализация** перед подсчётом. BPC = `CE / (ln2 × chars_per_token)`; RU: BPB ≈ ½ BPC.
2. **Speed-in-bytes fuse.** Скорость в символах/с **и** байтах/с раздельно, не токенах/с.
3. **Data-budget fuse.** Бюджет нормализуется по байтам/символам или FLOPs на байт.
4. **Total-memory fuse.** Память запроса ≠ только KV: GDN recurrent + MTP + lookup кэши + MoE буферы.
5. **🆕 Regularization-alignment fuse.** Любое сравнение архитектур (AR ↔ гибрид ↔ dLLM ↔ block-diffusion) некорректно без выравнивания стека стохастической регуляризации: input token-dropout, MLP-dropout, weight-decay, label-smoothing. Иначе «эффект архитектуры» = конфаунд «эффекта регуляризации». Точки «AR без маскирования» и «AR с адекватной регуляризацией» — обе обязательны в матрице.
6. **🆕 Cross-paradigm BPB fuse.** AR NLL и dLLM NELBO не сопоставимы напрямую. Определить единый BPB-эквивалент (variance-reduced ELBO, та же NFC-байтовая нормализация) ДО кросс-парадигмного сравнения.
7. **🆕 Metadata guards.** (A) все n-граммные операции по телу без prepended-метаданных; (B) BPB-знаменатель без metadata-байт (masked loss на них); (C) cooldown 10–20% шагов без метаданных, инференс всегда чистый; (D) metadata — часть fuse #5.
8. **🆕 Proxy-transfer fuse.** Ранжирование данных/гиперпараметров на прокси неустойчиво к LR. Сравнение рецептов — при tiny-LR (1e-5–1e-6); абсолютные доли/пороги перепроверять на целевом масштабе.

## 2. Компоненты-кандидаты (пространство поиска)

### 2.1. Токенизатор — «Фаза 0a»
Проблема: BPE рвёт русские морфемы → без совместимого токенизатора морфемный lookup (§4.2) не проверяем.
- **Путь A:** Morpheme-Aware BPE/Unigram (pymorphy3/DeepPavlov). Токены=морфемы; словарь растёт, эмбеддинги теряются.
- **Путь B:** BPE + character-offset morpheme tagger. Совместимость с BPE; морфема «размазана».
- **Baseline:** стандартный BPE (LLaMA/Qwen-style).
- **Фиксация v5.0:** словарь **50K единый для всех конфигураций** абляции (иначе конфаунд). 32K — fallback только при жёсткой памяти, тоже единообразно.
- **Критерии:** BPB/BPC, скорость ток./деток., совместимость с lookup, downstream.

### 2.2. Позиционное кодирование — «Фаза 0b»
RoPE деградирует на 32K; эффект различен по слоям (GDN — рекуррентный, без явного RoPE; MLA — partial RoPE).
- **Диапазон:** RoPE / YaRN / NTK-aware / LongRoPE; доля partial RoPE 25/50/100%.
- **Проверки:** длина обучения vs оценки; стоимость length-extension; гибридные слои отдельно.
- **2.2-доп. Длинный контекст:** RULER-подобные, многоигольные, дистракторные, доменные (найти норму, проверить условие, сопоставить пункты, извлечь обязательства, противоречия), длинная генерация. Отдельно prefill/decode latency, память.

### 2.3. Гибридное внимание
- **Диапазон:** линейное:полное 1:1…7:1; линейное — GDN/Mamba-2/DeltaNet; полное — MLA/GQA/DSA/QSA; позиции полных — равномерно/кластерно.
- **Источники:** Qwen3-Next (GDN 3:1), GigaChat 3.5 (MLA+GDN 1:3), DeepSeek V3.2 (DSA), Olmo Hybrid, Kimi Linear.
- **Открытый вопрос:** оптимум для русского домена не опубликован.

### 2.4. MoE с fine-grained экспертами
- **Диапазон:** N=64/128/256/512; гранулярность; shared с/без; aux-loss / aux-loss-free / Expert Drop / Seq-Aux; capacity 1.0/1.25/1.5; обработка дропов; температура роутера; sharding TP/EP/hybrid; prefetch predictability.
- **Метрики:** качество при фикс. активных; Collapse Rate; Macro-pool entropy; Prefetch hit; Batch fragmentation; HBM BW.
- **Батчинг:** 1/8/32, mixed/same-domain.

### 2.5. Стабилизация активаций
- **Диапазон:** GatedNorm (RMSNorm + low-rank гейт, 2·sigmoid-init) vs RMSNorm; Gated Residual (multi-stream Hyper-Connections) vs один; комбинация (не опубликована); сэндвич 4 vs 2 норм.
- **Метрики residual/attention sinks:** доля внимания на BOS/спец; норма residual по слоям; доля каналов с экстремумами; FP8-стабильность.

### 2.6. Скейлинг/нормализация в MLA
QK-Norm vs learnable alpha_q/alpha_kv vs оба; инициализация alpha из размерностей vs константа; partial RoPE.

### 2.7. N-gram / lookup-память
- **Диапазон:** позиция (вход/средние/ветвь); гейт (скаляр/покомпонентный/cross-attn); размер; уровень (BPE/морфемы/морфо-синтаксис).
- **Ограничение:** cross-attention добавляет FLOPs — мерить прирост качества против FLOPs.
- **Иерархия:** HBM/DRAM/NVMe + хеширование + PQ.
- **Контроль:** contamination audit (§6). **Стриминг:** oracle vs streaming отдельно (§7).
- **Бэк-офф:** перед Engram — token/char/lemma n-gram lookup, кэш последних n.

### 2.8. MTP-головы
0/1/2/3; последовательные vs параллельные; тренировочная цель vs спекулятивный декод. Критерий: прирост качества+ускорение против стоимости.

### 2.9. 🆕 Стохастическая регуляризация
Механизм подавления memorization при многократном повторении ограниченного корпуса. Доминирующий фактор super-data-learner эффекта (не двунаправленность).
- **Input token-dropout:** доля {0.0–0.5}, способ `[MASK]`/random/zero-emb/DropToken; маска независимо на пример и шаг; **target не трогаем**; только обучение.
- **EntroDrop:** маскировать низко-энтропийные (уже выученные) токены.
- **Curriculum:** старт низкой доли → рост во второй половине.
- **MLP-dropout / weight-decay:** AR с усиленными может догнать dLLM; MLP-dropout эффективнее attention-dropout.
- **Двойной val-лог (обязателен для AR):** `val_clean_bpb` (инференс) + `val_masked_bpb` (обучение). Тревога: masked↓/clean↑ = переусердствовали (distribution shift).
- **Связь с fuse #5:** регуляризация — ось, выравниваемая между всеми сравниваемыми архитектурами.

### 2.10. 🆕 Metadata conditioning
Дешёвый рычаг data-efficiency + steering без роста объёма корпуса.
- **Ускорение:** MeCo (Metadata Conditioning then Cooldown) — prepended URL/домен → то же downstream на ~33% меньше данных. Надёжнее всего URL/идентификатор источника.
- **Steering:** форматные теги (договор/решение/акт/заключение) → управление стилем в стиле CFG.
- **Fine-grained:** тонкогранулярные quality-скоры ускоряют; грубые темы — нет. **Synergy:** DCLM fastText score из 8.3.1 = готовый сигнал.
- **Интеграция:** prepending `[URL: ...] <текст>`; learnable meta-tokens (masked loss); aux-предсказание метаданных.
- **Cooldown ОБЯЗАТЕЛЕН** (fuse #7C): последние 10–20% шагов без метаданных.
- **Ограничение:** эффект URL сильнее на длинных промптах (5-shot).

### 2.11. 🆕 Diffusion / block-diffusion (кандидат Track C)
- **dLLM-статус:** 100B (LLaDA2.0), коммерческие (Mercury 1109 ток/с). Качество догоняет AR (ADLM +25.4% PPL, >AR по MAUVE; LLaDA2.0-flash 73.18 vs Qwen3-30B-A3B 73.60).
- **Цена:** +20–30% стоимости обучения (двунаправленность не параллелится по seq); compute-optimal = меньше params, 1.5–5× больше токенов (Quokka).
- **Инференс:** без KV-кэша = ахиллесова пята; решения Eso-LM (каузальное+KV), D2F (блочно-AR, >2.5× GSM8K), BD3 (block-diffusion).
- **Решение:** Track C открывается **только** после гейтированного crossover-эксперимента H1 (§9, Фаза 3+). Не в критическом пути C0.

## 4. Потенциальные точки оригинальности (с честными прецедентами)

- **4.1 GatedNorm + Gated Residual** (A, низкий риск). Компоненты опубликованы поотдельности, комбинация — нет.
- **4.2 N-gram lookup для русского домена** (B, высокий). Прецеденты: morphology-aware tok., char-level для флективных.
- **4.3 Context-Gated Engrams** (B, высокий). Прецеденты: Memorizing Transformers, RETRO, UniMem, MemoryLLM. Риск: cross-attn FLOPs.
- **4.4 Syntactic Attention Bias / Aux Loss** (B, высокий). Прецедент Strubell 2018. Aux-loss устойчивее attention-bias → начинать с него.
- **4.5 Иерархический роутинг MoE** (B, средний). «Under-explored»; ценность в prefetch predictability.
- **4.6 Калибровка гибридной пропорции под домен** (A, низкий). Оптимум RU-домена не опубликован.
- **4.7 Morpho-Syntactic Engram Keys** (B, высокий). `[NOUN|судья|nom]→[VERB|вынести|pf]:nsubj`; свободный порядок/падежи.
- **🆕 4.8 Регуляризация vs архитектура** (B, высокий концептуальный). Если AR+регуляризация догоняет dLLM — advantage не архитектурный; меняет интерпретацию направления.
- **🆕 4.9 Metadata-driven steering для домена** (A/B). Форматные теги + fine-grained quality как канал управляемости юр. стиля.

# Часть II. Протокол

## 5. Валидационный срез и доменный бенчмарк

### 5.1. Принципы
Строится первым; заморожен навсегда; стратифицирован; достаточен для статистики; не пересекается с тренировкой по времени/источнику/n-граммам.

### 5.2. Состав
- **A. Held-out языковая (≥10M токенов в полном масштабе; ≥2M для C0-прокси).** Сплошной текст для BPB/BPC, word-internal, диагностики гейтов.
- **B. Доменный бенчмарк (3000 в полном; 300–500 для C0).** Размеченные задачи.

**Оси (полный масштаб):** тип задачи; длина (<2K/2–8K/8–32K); поддомен; сложность; языковое явление (Track B). Правило ≥50/ячейку.

**🆕 C0-срез (правка A3/A4):** активны **2 оси** — task type (4: извлечение, применимость нормы, проверка условия, противоречие) × длина (2 бакета **<1K, 1K–2048**) = **8 ячеек**, ≥50/ячейку → 400 примеров. **V-B фильтруется ≤2048 токенов** (контекст C0); бакеты 2–8K / 8–32K — полный бенчмарк / Фаза 0b. Оси поддомен/сложность/языковое-явление — не для C0.

### 5.3. Шесть типов задач (полный)
Извлечение сущностей/обязательств; применимость нормы; проверка условия; противоречие; multi-hop; длинный контекст 32K. Track B-диагностика: согласование на дистанции, управление падежами, кореференция, отрицания.

### 5.4. Защита от пересечения (три уровня)
Временное (`T_cutoff`); источниковое; n-граммная дедупликация 13-граммы (0 пересечений, сверхчастотные >10 доков игнорируются, но **не вырезаются из V-A** — правка B7). **🆕 Metadata guard A:** 13-граммы по телу без prepended-метаданных.

**🆕 T_cutoff = 2024-01-01** (FineWeb2-HQ собран 2013–апр2024; запас 3–4 мес). T — до cutoff; V-A — после; V-B — любая дата (не в тренировке). Документ без даты = «старый», может быть в T; источник без даты не годится для V-A.

**🆕 C0 V-A: отступление от чистого cutoff (зафиксировано).** Весь wiki-дамп выложен в T (`--all`) → cutoff-разделение для wiki неприменимо (post-2024 wiki уже в T). V-A для C0 собран так:
- **wiki-компонент: document-level held-out split** — 5% статей откалывается по хешу заголовка в V-A и **исключается из T** (любые даты, не cutoff). Защита от утечки **сильнее** cutoff, но V-A-wiki не «свежая» (репрезентативна T, который тоже wiki-тяжёлый).
- **news-компонент: cutoff соблюдён** — Kasymkhan + bruhwalkk, только ≥ 2024-01-01, и эти источники не в T (источниковое разделение).
- **Персистентность:** held-out wiki ID (хеш заголовков) = **постоянный ban-list** — любая будущая T-сборка из того же дампа обязана их исключать.
- **Финальная модель:** V-A/V-B пересобираются крупнее (≥10M / 3000) по §5.2; стратегия разделения — заново под полный масштаб. C0-слайсы черновые, не переиспользуются как есть.

### 5.5. Заморозка
Финальная дедупликация → стратификация → SHA-256 + Merkle root → запись (дата/версия/хеш/состав/источники/T_cutoff/дедуп) → физическое разделение (write-once, нет доступа у тренировочного пайплайна). Изменение = новая версия.

### 5.6. Чего нельзя
Собирать валидацию после абляций; добавлять «сложные» примеры для баланса; калибровать пороги после первого прогона; смешивать held-out и бенчмарк; интерпретировать BPB без downstream.

## 6. Contamination audit
Двухступенчатая: Bloom (точные/стриминговые) + MinHash (near-dup).
- **Bloom:** 13-граммы, stride w/2, FPR 10⁻⁴–10⁻³, нет ложноотрицательных.
- **🆕 Для C0:** «настоящего» Bloom под таблицу нет — **exact 13-gram set difference** V-A/V-B против T (правка B6).
- **MinHash:** shingles char-5/token-n, Jaccard 0.7, только для кандидатов после Bloom.
- **Контекст ключа:** n-грамм из контекста ключа → подозрителен.
- **Сверхчастотные >10:** не для отсечения, помечаются низкоинформативными.
- **Контроль покрытия:** removal rate (норма доли %, аномалия >10%); ручная верификация precision ≥80% на 100–500.
- **Верификация:** sanity present/absent; фактический FPR на 10⁵; removal rate; документирование.

## 7. Протокол streaming lookup
- **Speculative (WORD_START, низкая надёжность)** → word-internal PPL. **Confirmed (WORD_COMPLETE, высокая)** → downstream (согласование, местоимения, аргументы). Не смешивать.
- **Инъекция в токен-границу:** энграмм завершённого слова W инжектится в первый токен после W до его KV — причинность сохранена, кэш инкрементален.
- **Мягкий лукап:** `e = Σ pᵢ·Lookup(Kᵢ)`, топ-k, нормировать после суммы.
- **Три фикса:** BOUNDARY_AND_NEW_WORD; явный режим speculative (A: только WORD_START; B: каждый WORD_PENDING — отдельная абляция); train/test согласованность (та же позиция, тот же источник ключа, тот же шум).
- **Автомат:** IDLE / WORD_START / WORD_PENDING / BOUNDARY_AND_NEW_WORD / WORD_ABORT.
- **Метрики по состояниям;** иерархия HBM/DRAM/SSD+PQ; prefetch голова L-4; бюджет морфо-анализа с graceful degradation; lookup batch coalescing.

## 8. Построение таблицы энграммов
- **Целевые (фиксируются до построения):** 10M–100M записей; частотный порог ≥5; доменных ≥60%; ключ 2–4 леммы+связи; FP16 горячий + INT8+PQ тёплый/холодный.
- **Воронка:** (1) частотный морфо-теггер (pymorphy3/Natasha, CPU) → 1–5% кандидатов; (2) полный парсер (Stanza/DeepPavlov) только кандидатов ~1–3 дня CPU; (3) contamination audit.
- **Формат ключа:** леммы/POS/морфо/relation/word_order (свободный порядок RU).
- **Хранение:** хеш-таблица GPU / LSM SSD; xxHash/MurmurHash3.
- **5 проверок до абляции:** coverage 60–80%; key precision ≥90%; diversity (нет типа >50%); contamination (removal в норме, precision ≥80%); latency (горячий<1мс/тёплый<10/холодный<100).
- **Бюджет:** CPU-кластер ~1 неделя, без GPU.

## 10. Абляция speculative vs confirmed
- **Конфиги:** C0 (—/—), C1 (spec), C2 (conf), C3 (оба), C1-mis/C2-mis (контроль позиции: та же информация, сдвиг позиции).
- **Ключ:** C2 vs C2-mis — чистый тест позиционной гипотезы; снимает конфаунд числа параметров.
- **Где мерить:** word-internal (spec), boundary-token (conf), post-boundary/downstream (conf), long-span ≥20 (conf).
- **Критерии независимости:** аддитивность; нет кросс-загрязнения (|Δ|<ε_cross); нет интерференции; ε=1.96·σ_paired (фикс. до эксперимента); потолок метрики фиксировать до интерпретации.
- **Матрица результатов:** аддитивность/супераддитивность/частичная интерференция/избыточность/прямая интерференция/кросс-загрязнение.

## 11. Диагностика гейтов
- **Лог:** gate_spec/gate_conf по [B,T]; token_type; word_length; distance_to_boundary; morpho_confidence; e_spec/e_conf нормы; фактические vs ожидаемые позиции; loss по семьям.
- **Визуализации:** heatmap gate×position×layer; scatter cos(e_spec,e_conf); timeline; correlation matrix.
- **Пороги проблем:** saturation (>0.9)+( <0.1) >0.95; anti-corr <−0.5; redundancy |cos|>0.9; injection mismatch >0.01.
- **Исправления:** saturation (init std0.01/bias−2.0, LR×0.1, L2); anti-corr (разделить позиции, последовательная инъекция, multi-stream, ортогональность); redundancy (понизить размерность, ортогональный loss, отключить один); mismatch (BOUNDARY_AND_NEW_WORD, assertion, визуализация).

## 12. Gate 3: финальное решение Engram vs RAG
- **Вход:** ΔКачество (по своей семье), ΔLatency TTFT, ΔThroughput, ΔCost, флаг contamination.
- **Флоучарт:** валидность (contamination/mismatch<1%/saturation<95%) → качество (Δ>ε_q, CI lower>0) → вето по стоимости (относ.+абсолют.) → latency/throughput → конфигурация (покрытие ≥95% Engram-primary / 70–95% гибрид / else).
- **🆕 Предусловие:** regularization-alignment fuse выполнен (иначе Δ неатрибутируем).
- **Пороги по сценариям** (чат/пакет/юр/edge/R&D) — стартовые, калибруются на прокси однократно до основной абляции.
- **Сегментация по умолчанию** для смешанной нагрузки.
- **Покрытие:** ≥95% Engram-primary; 70–95% гибрид (дефолт); 50–70% RAG-primary+ускоритель; <50% RAG-only.
- **Фиксируется до Gate 3:** сценарий, ε_q/ε_l/ε_t/ε_c, вето, порог покрытия, что = отрицательный результат. После абляции не меняется.

# Часть III. Исполнение

## 13. Go/no-go ворота
- **Gate 0 (фундамент):** морфемный токенизатор улучшает BPB но бьёт симв/с → компромисс/Путь B; YaRN/NTK/LongRoPE не дают качества @32K → не строить длинный контекст.
- **Gate 1 (гибрид):** Парето качество+KV+скорость+стабильность.
- **Gate 2 (MoE):** лучше dense по качество/скорость/память/стабильность экспертов.
- **🆕 Gate 1.5 (регуляризация):** стек регуляризации выровнен между всеми сравниваемыми конфигами; `val_clean_bpb` стабилен; двойной лог ведётся.
- **Gate 3 (Track B):** компонент лучше (1) базовой, (2) +улучшенные данные, (3) +простой кэш, (4) +RAG. Улучшает BPB но проигрывает RAG — важный отрицательный.
- **🆕 Gate C (diffusion):** открывается только если H1 crossover ранний и значимый при нашем бюджете.

## 14. Статистический протокол
- **3 сида** на конфигурацию (2 запрещены для основного сравнения — правка C2; исключение только с pooled σ из smoke + документирование).
- Парные сравнения на одних срезах; ДИ на Δ (bootstrap/paired t); заранее заданный ε.
- Фиксация конфигов: все гиперпараметры одинаковы между C0–C3, кроме флагов инъекций **и регуляризации/metadata (выровнены)**.
- **🆕 Двойной val:** `val_clean_bpb` (primary) + `val_masked_bpb` (диагностика регуляризации).
- **🆕 Pre-registered порог первого сигнала:** гибрид улучшает BPB ≥1% relative (CI lower bound >0) И speed не хуже 10% И memory не хуже 10%; иначе ранний отрицательный.

## 15. Критический путь к первому сигналу
**Недели 1–2:** собрать валидационный срез (T_cutoff=2024-01-01, V-A ≥2M, V-B 8 ячеек ≤2048, IAA κ≥0.6, write-once+хеш); зафиксировать пороги ε; подготовить корпус, очистить от валидации.
**Недели 3–4 (Фаза 0, параллельно):** токенизатор 50K (0a); инференс-профиль (0c); окружение+детерминизм (RNG/dataloader state в чекпоинт); smoke 10M (LR-sanity, детерминизм, свип регуляризации).
**Недели 5–8:** прокси ~152M C0 (чистый AR, MHA, 2.5B токенов, 9500 шагов, warmup 500, FLOP-matched 2.28e18, 3 сида, выровненная регуляризация); одна абляция гибридного внимания (этап 1).
**Первый сигнал:** Парето-выигрыш гибрида над C0? Нет → ранний дешёвый отрицательный, экономия бюджета. Да → дальше MoE/Track B; **после Фазы 1 — гейтированный crossover H1** (решает Track C).

## 16. Что документ не утверждает
- Не дизайн GigaChat (один из baseline-ов).
- Не гарантия оригинальности (прецеденты для каждого п.4).
- Не финальный план (пересматривается по Фаза 0–1).
- Отрицательный результат — тоже результат.
- «На порядки быстрее» — не обещание.
- Прокси ~150M–1B может не перенестись (особенно MoE).
- **🆕 Не утверждает, что dLLM лучше/хуже AR** — только что сравнение требует fuse #5/#6 и гейта H1.

## 17. Чего не переоценивать
1. Прокси-масштаб (MoE иначе на больших).
2. Лингвистические новшества (реалистично — устойчивые проценты).
3. Морфемный lookup (+0.1% BPB при парсере/кэше/стриминге может не окупиться).
4. Иерархический роутинг (хорош для узкого домена, плох для смешанного батча).
5. RAG может победить архитектурную память (граница применимости).
6. **🆕 dLLM-инференс «10×» ≠ дёшево:** стоимость обучения +20–30%+ и data-hunger; без H1-гейта не бросаться.
7. **🆕 Метаданные — не магия:** эффект зависит от типа/гранулярности/длины промпта; без cooldown и guards — вред.
8. **🆕 Precision без железа:** FP8 выбран без подтверждения нативных ядер (Hopper/Blackwell) → нет ускорения или нестабильность; для ~150M-прокси выигрыш маргинален, реальная цена точности — на 1B+/MoE (см. PLAN-addendum-precision).

## 18. Практические риски
1. Вычислительный бюджет (полный прогон + таблица — существенны).
2. Паралич анализа (жёсткие дедлайны, бинарные DoD).
3. Командные роли (4 компетенции; один человек → приоритизация по §15).
4. Перенос прокси→масштаб (после Фазы 1 — прогон на 1B, затем 7B+).
5. **🆕 Конфаунд регуляризации** (high): без fuse #5 все сравнения под сомнением.
6. **🆕 Нестабильность прокси-ранжирования** (ICLR2026): tiny-LR патч для сравнения рецептов.
7. **🆕 Кросс-парадигмный BPB** (high): без fuse #6 AR↔dLLM несопоставимы.
