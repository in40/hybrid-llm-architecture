## 2. Условия (arms)

### 2.1 Подтверждающее (confirmatory) — ровно одно сравнение
**A1 — гибрид GDN 3:1** (гипотеза H1, единственная проверяемая):
- 12 слоёв; **полное внимание (MHA, как C0) в слоях 4, 8, 12** (1-индексация, равномерно); остальные 9 — **Gated DeltaNet** (рекуррентный state, chunked training).
- **FLOP-matched:** полные FLOPs прогона A1 в пределах **±0.5% от достигнутых FLOPs A0** (baseline — факт A0, не теоретический референс). Подгонка **только через intermediate_size MLP**; d_model, число слоёв, голов и head_dim **не меняются** (избегаем конфаунда head-dim/RoPE). Точный конфиг фиксируется в GitHub **до** запуска A1; фактические FLOPs и число параметров **репортуются** по каждой arm. FLOPs считаются **аналитически из frozen-конфигов**; в качестве sanity-check на калибровочном прогоне A1 репортится **профайлерный кросс-чек** (flop-счётчик torch.profiler на ~100 шагах).
- **Ожидаемый масштаб конфаунда ёмкости (явная арифметика):** экономия GDN-слоёв против MHA оценивается **S ≈ 4–12%** от FLOPs/токен (экономия квадратичного члена при L=2048 минус доп. проекции гейтинга GDN); доля MLP в FLOPs/токен **f_MLP ≈ 0.48** (SwiGLU 3-матричный MLP = 85M из 151.7M параметров). Реинвест экономии в ширину MLP: **Δi/i = S/f_MLP ≈ 8–25%** (3072 → ~3300–3800) → **ожидаемо A1 ≈ 159–173M параметров (+5–14% к A0)**. Точные значения — из frozen-конфига и профайлерного кросс-чека; арифметика воспроизводится в config-скрипте на GitHub.
- Всё остальное — байт-в-байт как A0: данные, токенизатор, регуляризация, LR-плейка, число шагов, сида, детерминизм.
- **Оценка (estimand):** относительное преимущество **семейства архитектур при равном тренировочном компьюте** (quality-per-FLOP). Это НЕ изолированный эффект типа внимания при равном числе параметров: A1 может иметь иное число параметров (следствие подгонки ширины), и дизайн не разделяет «механизм внимания» vs «ёмкость». Формулировки результатов: «гибридное семейство эффективнее по компьюту», а не «GDN лучше MHA».
- Гипотеза: **BPB(A1) < BPB(A0)** при неухудшении скорости/памяти.

### 2.2 Разведочные (exploratory, регистрируются, но не несут подтверждений)
- **A2** — Mamba-2 (SSD) 3:1, те же позиции полных слоёв. **Запускается.**
- **A3** — GDN 1:1 (6 полных / 6 линейных). **Запускается.**
- **A4** — победившее линейное семейство + GQA (full: 12 q-heads / 4 kv). **Условный запуск** (правило ниже).
- **A1′** — GDN 3:1 при **baseline-ширинах** (d=768, MLP 3072, без FLOP-подгонки; суммарный компьют ниже A0). **Условный запуск** (правило ниже). Смысл: точка «равные параметры» для грубой декомпозиции «механизм vs ёмкость»: если A1′ ≈ A0 по BPB при меньшем компьюте — выигрыш A1 в основном от ёмкости; если A1′ уже лучше A0 — есть вклад механизма.
Каждый exploratory arm = те же 3 сида. Интерпретация только гипотезо-порождающая.

**Правило запуска A4 (предзаданное):** A4 запускается (3 сида) **только если** хотя бы один из A1 или A2 прошёл **полный** гейт раздела 4. Семейство в A4 = победившее (прошёл A1 → GDN+GQA; прошёл только A2 → Mamba-2+GQA; прошли оба → GDN+GQA). Если ни один не прошёл — A4 регистрируется как «not run».

**Правило запуска A1′ (предзаданное):** A1′ запускается (3 сида) **только если** A1 прошёл полный гейт раздела 4 (нужен декомпозиционный контроль именно для победившей конфигурации).

## 3. Метрики
- **Первичная:** `val_clean_bpb` финального чекпоинта (step 38147), NFC, bits-per-byte на frozen V-A (фикс. подмножество 256×2048).
- **Диагностическая:** `val_masked_bpb` (страховка от выигрыша «за счёт маскирования»).
- **Стоимостные (протокол замера зафиксирован):**
  - *Throughput* = UTF-8 байтов обработанных токенов / wall-clock, медиана по окну **шагов 36000–38147**, интервалы eval и checkpoint-save **исключаются** из времени; замер на той же GPU без посторонних процессов.
  - *VRAM* = `torch.cuda.max_memory_allocated` (не reserved), счётчик сброшен на шаге 36000, пик по тому же окну.
- **Вторичная подтверждающая:** V-B downstream (8 ячеек: извлечение обязательств / применимость норм / проверка условий / противоречия; exact-match/F1/accuracy против gold). Baseline-значения V-B для A0 репортуются до оценки вето; если mean F1 A0 ≤ 0.05, вето по V-B объявляется **неинформативным** (пол near floor) и не используется.

## 4. Статистический план (n=3 на arm)
Единица наблюдения — **сид**; сравнение **спаренное по id сида** (42↔42, 123↔123, 456↔456).

Для каждого сида s: `g_s = (BPB_A0(s) − BPB_A1(s)) / BPB_A0(s)` (относительный выигрыш гибрида).
`ḡ = mean(g_s)`; **95% CI = ḡ ± t₀.₉₇₅,df=2 · s_d/√3** (t = 4.303).

**Оценка разброса и мощность (честная):** единственная измеренная пара сидов A0 (42 vs 123, сопоставимые шаги) даёт |Δ| ≤ 0.0007 bpb, но **по одной паре s_d не оценивается** (доверительный интервал для s_d практически неограничен). Поэтому:
- плановая консервативная оценка **s_d ≈ 0.002 bpb (~0.2% rel)** → при n=3 гейт требует mean gain ≳ **1.5%**;
- **триггер расширения: s_d > 0.002 bpb** (по 3 наблюдаемым парам) → добавляются сида 789 и 1024 в **оба** confirmatory arm (n=5, df=4);
- если расширение не сработало и гейт не пройден при n=3, результат репортируется как **«недостаточно доказательств преимущества ≥1%»**, а не «эффекта нет»;
- **шум самого триггера признаётся:** выборочное s_d по 3 парам имеет df=2 и очень широкий интервал (при истинном s_d=0.002 триггер сработает лишь примерно в половине случаев). Это принятое осознанное ограничение (цена гарантированного n=5 — +4 прогона ≈ +150 GPU-ч); альтернатива «расширение по верхней границе CI(s_d)» фактически означала бы n=5 всегда и отклонена по бюджету;
- иного расширения не допускается.

**Гейт решения (все условия обязательны):**
1. `CI_lower(ḡ) ≥ 1.0%` (первичный критерий);
2. достигнутые FLOPs A1 в пределах **±0.5% от достигнутых FLOPs A0** (иначе сравнение невалидно — пересбор конфигурации до прогонов);
3. throughput A1 ≥ 0.9 × throughput A0 (байтов/с, протокол §3);
4. пиковая VRAM A1 ≤ 1.1 × VRAM A0;
5. **Вето V-B (однозначная формулировка):** вето срабатывает **тогда и только тогда**, когда относительное падение mean F1 > 2% **И** абсолютное падение > 0.01; абсолютное условие проверяется **только при** baseline mean F1 > 0.05; если baseline mean F1 ≤ 0.05 — вето объявляется неинформативным и документируется.
Все выполнены → «гибрид лучше». Иначе → «не доказано лучше» (отрицательный результат публикуется как есть).

**Замораживание:** код анализа (формулы, скрипт) и точные конфиги arms коммитятся в GitHub **до** получения финальных BPB A1. Первичная метрика — только финальный чекпоинт; промежуточные кривые в решение не входят.

## 5. Правила исключений и нештатных ситуаций
- Прогон исключается/перезапускается при: non-finite loss; **или** train-loss > 1.2 × EMA(train-loss) с half-life 200 шагов на протяжении > 1000 последовательных шагов. Перезапуск — тот же сид; причина фиксируется в логе.
- **Исключения репортуются по каждой arm** (число, причины). Если исключения коррелируют с arm (например, гибрид спайкует чаще) — это **результат об устойчивости архитектуры**, а не шум, подлежащий сокрытию.
- Если A1 не влезает в VRAM при micro_batch=6 — micro_batch снижается (6→4→3) с сохранением эффективного batch=32; факт фиксируется, сравнение скорости ведётся в байтах/с при максимальном влезающем micro_batch **для обоих arm одинаково** (A0 тоже на пониженном, если требуется).
- **Resume-эквивалентность:** resume из чекпоинта восстанавливает optimizer/RNG-состояния; эквивалентность непрерывному прогону проверяется A/B-тестом (500 шагов подряд vs с resume-разрывом; совпадение loss в пределах шума) и результат раскрывается в анализе.
- Калибровочный прогон A1 (100–200 шагов до основного) — замер скорости/VRAM/стабильности **и профайлерный кросс-чек аналитических FLOPs** (torch.profiler flop counter); в анализ BPB не входит, регистрируется как pilot.

## 6. Раскрытие предшествующих данных (foreknowledge)
- A0 частично наблюдался до регистрации: seed 42 завершён, seed 123 в процессе. Это **референс, а не тестируемое условие**; дизайн гибридного arm от этих значений не зависел.
- Development-итерации пайплайна (некаузальный attention-mask, токенизатор без пробелов, bad init) исправлены **до** фиксируемого протокола; они не являются частью подтверждающего результата.
- Ни один гибридный arm ещё не запускался: **данных по H1 на момент регистрации не существует.**
- **Ревизия 2026-11-15 (до сабмита):** по итогам внутреннего методологического ревью уточнены: estimand (matched-compute семейства, не «только внимание»), FLOPs-допуск ±2%→±0.5% (только MLP-width), триггер расширения n=5 (0.003→0.002) + консервативный power-план, вето V-B с абсолютным полом, критерий спайка (EMA half-life 200), протоколы замера throughput/VRAM, resume-эквивалентность, exploratory A1′. **Ни одно изменение не опиралось на данные по гибриду (их нет).**
